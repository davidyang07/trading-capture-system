# event-contracts

Owns every Avro event schema in the system and is the enforceable event-contract catalog. Event
DTOs are generated from these schemas rather than redefined in individual services.

## Contents

- `src/main/avro/*.avsc` — the shared `EventMetadata` envelope, the shared `ValidationErrorDetail` error record, and the seven domain events (`AllocationReceived`, `AllocationValidated`, `AllocationRejected`, `ExecutionsAllocated`, `ExecutionsReleased`, `ExceptionReported`, `SettlementRequested`). Every event embeds `EventMetadata` as its first field.
- `com.tradingcapture.events.EventTopics` / `EventHeaders` — hand-written constants for topic names (`tcs.<domain>.<event>.v<major>`, retry/DLT suffixes) and the Kafka headers that mirror the envelope (`x-event-id`, `x-correlation-id`, `x-causation-id`).

## Generated code

`SpecificRecord` classes are generated by `avro-maven-plugin` into `target/generated-sources/avro` during `generate-sources` — build output only: never hand-edited, never committed. Decimal logical types materialize as `BigDecimal` (`enableDecimalLogicalType`), `timestamp-millis` as `Instant`, `date` as `LocalDate`.

**Decimal contract:** Avro decimals carry a fixed scale — producers must `setScale(4)` (quantities/money) or `setScale(8)` (prices/rates) before building an event; a mismatched scale fails serialization rather than silently rounding.

## Evolution rules

Compatibility is **BACKWARD** per subject (TopicNameStrategy → subject `<topic>-value`). Evolution = additive optional fields with `null` defaults; anything else is a breaking change and requires a new `v<major+1>` topic with a parallel-publication window. `SchemaCompatibilityTest` demonstrates both directions; the compose Schema Registry enforces the same rule at runtime.

## Sync check

Whenever events change, the following must agree; `TopicConventionsTest` enforces the mechanical
relationships:

1. Seven outbound topics in `EventTopics` ↔ seven event schemas, names matched kebab-case.
2. Topic naming convention `tcs.<domain>.<event>.v<major>`.
3. Every event schema's `doc` names its topic; headers mirror the envelope constants.
4. This README and the service documentation describe the same topic keys and payload purpose as
   the `.avsc` files.

## Tests

`./mvnw -B -ntp -pl libs/event-contracts test` — serializer round-trips run against the Confluent `KafkaAvroSerializer`/`KafkaAvroDeserializer` with an in-memory `mock://` registry (registration under TopicNameStrategy asserted), plus BACKWARD-compatibility and convention checks.
